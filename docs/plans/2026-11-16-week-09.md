# Review of last week

## What went well

1. **You resolved the frame question with evidence.** The recorded **base_link → chassis_imu** transform has identity rotation, so the two z-axes are aligned. That directly supports comparing positive IMU **angular_velocity.z** with planar odometry yaw. This is much stronger than assuming the sensor mounting from its name.

2. **You implemented the substantive propagation correctly.** The code uses header timestamps, skips nonpositive intervals, integrates angular rate, wraps the heading, anchors it to an initial odometry yaw, and computes a wrapped final error. AI-generated interval selection and output plumbing were appropriate scaffolding; you owned the state propagation and error equations.

3. **You obtained a quantitative result.** The raw integration finished with an error of **-0.011309 rad (-0.647973°)** relative to odometry. That is small enough to show the implementation is broadly coherent while still leaving a measurable error for the next estimation step.

## Areas to improve

1. **Separate bias drift from sampling error.** A constant gyro bias causes heading error because the bias itself is integrated: **error ≈ bias × elapsed time**. It is not primarily caused by “missing information between samples.” Finite sampling and the right-endpoint integration rule can introduce a separate discretization error, especially during changing angular velocity, but that is a different mechanism.

2. **Be precise about what the IMU does and does not provide.** The gyro channel does not provide absolute heading, so gyro integration needs an initial condition. However, this simulated **sensor_msgs/Imu** message does have its orientation field populated, as you observed in Week 7. Ignoring that field was deliberate for this exercise—not evidence that the entire IMU message lacks orientation.

3. **Make the saved evidence and tests target the important failure modes.** The response records the final error but omits the comparison duration, starting/final headings, interval count, and endpoint timestamps printed by the analyzer. That leaves the cause of the error speculative. The tests also use zero angular velocity, so they verify output plumbing but not nonzero integration, angle wrapping, or nonpositive-dt behavior. Add small synthetic tests for the actual mathematics before extending the estimator.

## What to carry forward

**When two effects can produce similar output error—such as sensor bias and numerical discretization—name and test them separately rather than combining them into one explanation.**

# Week 9 — Add a heading observation update

**Generated:** November 16, 2026

## Weekly goal

Turn last week's open-loop gyro propagation into a minimal one-state prediction–correction estimator:

- **Predict** heading from IMU angular velocity.
- **Observe** heading from odometry.
- **Correct** a fraction of the wrapped disagreement.

The learning loop is:

**predict behavior → define the update → test wraparound → implement → compare raw and corrected estimates → explain the limitation**

This is a deliberately crude complementary-style heading filter, not an EKF. Odometry will serve as the observation because it is already recorded and understood. Since the corrected estimate is evaluated against that same odometry, the exercise demonstrates estimator mechanics—not independent proof that the estimate is more accurate in the real world.

## Estimated time

**65–90 minutes core**, including ROS environment startup, reviewing the existing analyzer, tests, implementation, running the saved Week 8 bag, and writing the interpretation.

Do not record a new bag unless the existing one is unavailable. Reusing the same data keeps the comparison controlled and avoids spending the whole session on simulator setup.

## Concrete tasks

### 1. Correct the mental model and make predictions — 10 minutes

Write these two mechanisms separately:

1. A constant gyro bias **b** creates approximately **b × T** radians of heading error after **T** seconds.
2. Discrete integration approximates the continuous motion between samples; its error depends on sample timing, the integration rule, and how quickly angular velocity changes.

Then predict:

- The raw final error should reproduce approximately **-0.011309 rad** if the same bag and interval logic are used.
- Applying odometry corrections should usually reduce error measured against odometry.
- A correction gain of zero should reproduce raw propagation.
- A correction gain of one should snap the estimate to each accepted odometry observation.
- A wrapped innovation near the **+π/-π** boundary should be small, not close to **2π**.

State the caveat before running the result: improvement against the correction source is expected and is not an independent accuracy test.

### 2. Add focused synthetic tests — 15–20 minutes

Extend the existing ROS-independent unit tests. AI may scaffold the test file, but choose and explain the cases yourself.

Add at least these checks:

1. **Nonzero propagation:** constant **0.5 rad/s** samples spanning two seconds should change heading by approximately **1.0 rad**.
2. **Nonpositive time:** a duplicate or decreasing timestamp should not add an integration interval.
3. **Wrapped innovation:** a prediction near **+π** and an observation near **-π** should produce a small correction across the boundary.
4. **Gain endpoints:** gain **0.0** leaves the prediction unchanged; gain **1.0** returns the observation modulo angle wrapping.

Run:

~~~bash
python3 -m unittest discover -s tools/analysis -p 'test_*.py'
~~~

The point is not broad test coverage. These cases protect the equations most likely to look plausible while being subtly wrong.

### 3. Implement one prediction–correction update — 25–35 minutes

Continue in **tools/analysis/analyze_imu_odom.py**. Keep the existing raw propagation running in parallel so the same bag produces a direct comparison.

Use a correction fraction named something like **correction_gain**, with a fixed core value:

~~~text
correction_gain = 0.05
~~~

Personally implement and understand:

~~~python
predicted_heading = wrap_angle(
    previous_heading + angular_velocity_z * dt
)

innovation = wrap_angle(
    observed_odom_yaw - predicted_heading
)

corrected_heading = wrap_angle(
    predicted_heading + correction_gain * innovation
)
~~~

AI may scaffold the stream matching. Use this causal rule:

- At each IMU sample, propagate both the raw and corrected headings.
- Use the latest odometry sample whose timestamp is not in the future.
- Apply each odometry sample at most once.
- Reject an observation if its age exceeds a documented maximum such as **0.10 s**.
- Count accepted and rejected observations.

Inspect the actual topic periods in the bag before accepting **0.10 s**; the limit should be comfortably larger than the normal odometry period but small enough to reject genuinely stale data. If the bag's timing makes **0.10 s** inappropriate, choose and document a different value rather than silently disabling the check.

Print:

- correction gain;
- observation-age limit;
- accepted and stale observation counts;
- mean absolute wrapped innovation;
- raw final heading and raw final error;
- corrected final heading and corrected final error; and
- the exact comparison duration and reference final odometry yaw.

Do not tune the gain until the error looks best. One fixed, predicted setting is enough.

### 4. Observe, measure, diagnose, and explain — 15–20 minutes

Run the analyzer on the same verified Week 8 turn bag and save the complete relevant output in the Week 9 response.

Answer in 5–7 sentences:

- Did raw propagation reproduce the previous result closely? If not, what changed?
- Did the corrected estimate move toward odometry as predicted?
- What were the raw and corrected final errors in radians and degrees?
- What does the innovation represent physically?
- What tradeoff does a larger correction gain make between gyro propagation and odometry observations?
- Why can stale observations make an estimator worse even when the observation values were once correct?
- Why is lower error against odometry not proof of better independent accuracy when odometry is also the correction source?

If the corrected result behaves unexpectedly, inspect in this order:

1. whether the innovation was wrapped;
2. whether the sign is **observation - prediction**;
3. whether an odometry message was applied more than once;
4. observation age and timestamp ordering;
5. gain units and range; and
6. only then sensor behavior.
