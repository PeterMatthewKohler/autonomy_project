# Week 10 — Measure heading drift during observation dropout

Generated November 25, 2026.

## Weekly goal

Use the existing offline heading estimator and saved turn bag to measure how a known gyro bias accumulates when observations disappear and how correction resumes. This is the final practical bridge toward uncertainty and a scalar Kalman filter. No new simulator recording is required.

## Estimated time

75–90 minutes core: 10 minutes setup/prediction, 15 minutes timestamp fix, 25–30 minutes experiment implementation, 15–20 minutes replay and analysis, 10–15 minutes troubleshooting reserve (stop at 90 minutes). Optional extension 15–20 minutes; absolute cap 120 minutes.

## Concrete tasks

### 1. Predict and establish baseline (10 minutes)

Reuse bags/week7_imu_stationary/positive_yaw. Run the existing analyzer with the same documented age limit and gain 0.05 used in Week 9. If the actual age limit was not saved, inspect the reported periods and choose/document a suitable limit. Record baseline output.

Choose a dropout covering the middle third of the shared IMU interval, using header timestamps. Inject a constant +0.02 rad/s into the gyro z channel in both experimental runs, without modifying the bag or odometry reference. Predict the additional heading error during the outage: approximately bias times elapsed time, relative to an otherwise identical unbiased prediction-only trajectory. A 3-second outage would add 0.06 rad (3.44 degrees). The actual total error also includes initial error and existing sensor/timing errors.

### 2. Repair timestamp handling (15 minutes)

In tools/analysis/analyze_imu_odom.py, reject duplicate/backward IMU samples without advancing the last accepted timestamp in both raw and corrected loops. Update the existing nonpositive-time test to expect 0.2 rad for the sequence above. Add the equivalent corrected-loop check with no observations. Run:

    python3 -m unittest discover -s tools/analysis -p 'test_*.py'

If the bag contains backward timestamps, document that fact and the resulting baseline change. Do not build a general clock-reset recovery system.

### 3. Add a small replay experiment (25–30 minutes)

Keep the current estimator and matching logic. AI may scaffold CLI arguments, trace collection and reporting. Add an optional bias and dropout window (defaults preserve existing behavior). During dropout suppress observation corrections, but continue consuming matches and propagating with the biased gyro. Do not queue observations for later application. Use the same bias in the continuous-observation and dropout cases.

Record a small trace of timestamp, estimated yaw, whether a correction was accepted, and time since last accepted observation. Use the existing initial heading as a common anchor; label it separately from accepted corrections. Evaluate against the unchanged odometry at nearby timestamps, reporting the timestamp mismatch. Use the last valid reference at or before each checkpoint and document its age. Do not feed evaluation-only observations into the dropout estimator.

Personally own the propagation equation, dropout gate, sign and units of bias, and definition of error. Test one synthetic interval with no observations and a known bias to verify the expected bias-times-time relationship.

### 4. Measure and explain (15–20 minutes)

Run three cases on the same bag, keeping gain, age policy, initial state and timestamps constant:

| Case | Gyro bias | Corrections |
|---|---:|---|
| Baseline | 0 | Continuous |
| Biased control | +0.02 rad/s | Continuous |
| Biased dropout | +0.02 rad/s | Suppressed in middle third |

For each report wrapped heading error at dropout start, end (before the first resumed correction), and final sample; accepted count and suppressed count; maximum time since last accepted observation. Record actual outage duration and baseline age limit. Compare biased dropout with biased control, not just the original baseline. The difference is not necessarily exactly bias times duration because the control continues correcting and the raw sensors have errors.

Explain whether error grew, whether it recovered after observations resumed, and why a final error alone can conceal an outage. If recovery is incomplete, report it rather than tuning gain. Odometry is a reference and correction source, not independent ground truth.
