# Week 1 — Understand the robot interface

**Generated:** September 22, 2026

## Weekly goal

Pick one Isaac Sim rover and understand exactly how your future autonomy software will observe and control it.

## Estimated time

**60–90 minutes core**, with an optional ~30-minute stretch task.

## This week's tasks

1. **Pick one rover and make it your standard platform for now.**
   Choose an Isaac Sim rover with an IMU and wheel odometry.

2. **Launch the rover and inspect its ROS 2 interfaces.**
   Use:
   ```bash
   ros2 topic list
   ros2 topic info <topic>
   ros2 topic echo <topic>
   ```
   Find the IMU, odometry, ground-truth pose, and velocity/control topics.

3. **Write down a tiny interface map.**
   Record the relevant topics, message types, and coordinate frames.

4. **Create one extremely small ROS 2 C++ node yourself.**
   Subscribe to one sensor topic, preferably odometry, and print `x`, `y`, and `yaw`.

5. **Move the rover and verify that your numbers make sense.**
   Manually move the rover and check that the node's output changes as expected.

## AI restriction

Write the subscriber yourself. If you are stuck for about 15 minutes, ask AI for an explanation rather than complete code. If you need generated code, be able to explain the constructor, subscription, callback, and `std::bind` or lambda.

## What not to do

Do not add an EKF, planner, SLAM, custom controller, elaborate project hierarchy, or refactoring.

## Definition of done

Isaac Sim and your C++ node run together while the rover moves and the node reports changing state. You can verbally explain the topic, message type, subscriber, callback, and information flow.

## If you finish early

Spend at most another **30 minutes** looking at the transform tree:

```bash
ros2 run tf2_tools view_frames
```

Figure out roughly how `world / odom` → `base_link` → `sensors` relate.

## Skills being practiced

ROS 2 C++, reading unfamiliar robotics interfaces, message types, coordinate frames, basic debugging, and writing a small robotics code piece without handing the whole problem to AI.

## End-of-week checkpoint

“Isaac publishes ____. My node subscribes to ____. That message contains ____. The callback gets called when ____. The position is expressed relative to ____.”
